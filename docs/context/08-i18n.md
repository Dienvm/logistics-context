# 08 — Internationalisation (VI default, EN, extensible)

## Routing

- Library: **next-intl** (App Router). `lib/i18n/routing.ts`:

```ts
import { defineRouting } from 'next-intl/routing'
export const routing = defineRouting({
  locales: ['vi', 'en'],
  defaultLocale: 'vi',
  localePrefix: 'as-needed',      // VI at root, EN under /en
  localeDetection: false,         // never auto-redirect by Accept-Language/cookie
  pathnames: {                    // static, code-owned paths; DB-driven slugs are resolved by the [slug] route
    '/': '/',
    '/kinh-nghiem': { vi: '/kinh-nghiem', en: '/guides' },
    '/tinh-cuoc': { vi: '/tinh-cuoc', en: '/shipping-calculator' },
    '/hang-cam-gui': { vi: '/hang-cam-gui', en: '/prohibited-items' },
  },
})
```

- App structure: `app/[locale]/…`; `<html lang={locale}>`; `setRequestLocale(locale)` in every layout/page that should render statically.
- `generateStaticParams` returns `{ locale, slug }` for every **published** translation only. A missing EN translation means **no EN page** (404), not a fallback to Vietnamese content.

## Slugs

- Each translation row owns its slug (`page_translations.slug`, `post_translations.slug`, `category_translations.slug`), unique per locale.
- VI slugs: no diacritics, keyword-first (`gui-hang-di-han-quoc`). EN slugs: natural English (`shipping-to-korea`).
- Changing a published slug must create a row in `redirects` (301 old → new) automatically in the admin action.

## Language switcher

- Links to the **equivalent** translation of the current entity (looked up by `page_id`/`post_id`), not just a prefix swap.
- If the equivalent is not published: hide the other locale or link to that locale's nearest hub (home / services / guides) with a note.
- Shows "Tiếng Việt" / "English" (not flags). Remembers nothing — URLs are the state.
- Optional dismissible banner "View this page in English?" when `navigator.language` starts with `en` and an EN equivalent exists.

## UI strings

- `messages/vi.json`, `messages/en.json`, namespaced by feature (`nav`, `cta`, `calculator`, `form`, `rates`, `footer`, `errors`, `consent`).
- ICU messages for plurals/numbers: `"transit": "{min}–{max} ngày"`, EN `"{min}–{max} days"`.
- A CI check fails if a key exists in one file and not the other.

## Formatting

| Item | VI | EN |
| --- | --- | --- |
| Money | `75.000 đ` / `75.000 đ/kg` (`Intl.NumberFormat('vi-VN')` + " đ") | `75,000 VND/kg` |
| Weight | `1,5 kg` | `1.5 kg` |
| Date | `20/10/2026` | `20 Oct 2026` |
| Phone | `0979 222 357` | `+84 979 222 357` |
| Time zone | Asia/Ho_Chi_Minh for display | same |

Prices are never translated or converted automatically; foreign currency hints (e.g. SGD) only if the business provides them.

## Translation workflow (content in Supabase)

1. Editor publishes the VI version (`status = published`).
2. "Create EN draft" action copies structure, machine-translates text fields (provider configurable — `NEEDS CONFIRMATION`), applies the glossary (`12-glossary.md`), sets `status = draft`, `source_updated_at = vi.updated_at`.
3. Reviewer edits → `review` → `published`. Hreflang appears only now.
4. When the VI row changes after `source_updated_at`, the EN row is flagged outdated (derived from timestamps, not a status value) and shows in an admin queue (it stays `published` until updated, unless the change touches facts — facts come from shared tables so they never drift).
5. SEO fields (title, description, slug) are reviewed by a human for every locale.

Priority for EN: home, 7 outbound routes, SG → VN, contact, about, calculator, prohibited goods, privacy policy.

## Adding a locale later

Add the code to `locale_code` enum + `routing.locales`, add `messages/<code>.json`, translate content rows, add to `sitemap.ts` alternates. No route or schema changes otherwise.
