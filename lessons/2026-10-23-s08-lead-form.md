# Specs miss threaded files, and lint:fix rewrites files outside the task

## What happened

- **Affected Areas were incomplete.** S-08 needed a new prop (`quoteHref`) on the calculator's "Nhận báo giá chính xác" action and a new placement value (`lead_form`). The spec listed the files where they are used (`calculator-page-actions.tsx`, `contact/constants.ts`), but not the files they pass through:
  - `calculator-section.tsx` and `quote-calculator.tsx` (server wrapper → island);
  - `get-calculator-labels.ts` (label resolver);
  - `contact-ctas.tsx` (an `Extract<ContactPlacement, …>` union);
  - `content/constants.ts` + `index.ts` (`PRIVACY_PAGE_KEY`).

  `/implement` had to stop and ask the owner to approve 5 out-of-scope files.
- **`lint:fix` rewrote files outside the task.** A lockfile refresh brought Biome 2.6, which formats Markdown and YAML. The repo-wide `pnpm lint:fix` in `/implement`:
  - reflowed the app's `AGENTS.md`/`README.md` (caught and restored);
  - reformatted `pnpm-lock.yaml`, which was then committed in Biome's format (chore commit ff0b375, code-review finding #3).

## What we learned

- `/feature-bug` builds Affected Areas from where a feature is *visible*. A new prop or enum value also touches every component and type on its path, and those files aren't obvious from the spec text.
- A repo-wide autofix changes whatever the formatter covers at that moment, and a dependency bump can widen that scope silently. `git status` after `lint:fix` is the only reliable check.

## Follow-up action

- **Action 1:** add a rule to the `/feature-bug` Affected Areas step. For each new prop, list every component from the composer to the consumer (server wrapper, island, child, label resolver). For each new enum/union value, list every `Extract<>`/union type or constant list that narrows it.
  - Target: `.claude/skills/feature-bug/SKILL.md`
  - Owner: Claude (next skill-maintenance change), reviewed by the owner
- **Action 2:** add a checklist item to `/implement`. Prefer scoped formatting (`pnpm -C 43logistics.vn exec biome check --write <changed files>`). After any `lint:fix`, `git status` must show only the task's files; restore anything else (lockfiles, Markdown) before staging.
  - Target: `.claude/skills/implement/SKILL.md` (self-review checklist)
  - Owner: Claude (next skill-maintenance change), reviewed by the owner
